OVERVIEW

何を作ったのか

警備会社の業務は「誰を・どの現場に・何時から立たせるか」という配置管理を起点に、 勤怠・請求・給与・法定教育・備付書類まで一続きにつながっています。 その全体を、隊員側と管制側の2つの画面から操作できる形で組み立てました。

📱

隊員は「押すだけ」

文字入力を極力なくし、選んでタップするだけで上下番報告が完了します。シニア層の隊員が多い現場を想定した設計です。

🖥️

管制は「一画面で把握」

誰が出発し、誰がまだ動いていないか。配置の過不足はどこか。判断に必要な情報を1画面に集約しています。

🔗

データは一本

配置を入力すると、勤怠・請求・給与・収支まで自動で連動します。転記作業とその過程で起きるミスが発生しません。

⚖️

法令対応を内蔵

新任20時間・現任10時間の法定教育の進捗管理と、警備員名簿など備付書類の出力に対応しています。

ARCHITECTURE

2つの画面と、その間を流れるデータ

同じデータベースを、立場の違う2種類の利用者が別々の画面から触ります。 隊員が打刻すれば管制の画面が即座に変わり、管制が配置を組めば隊員のシフトに反映されます。

賃金計算で対応している法令

  • 労基法37条　時間外25%（日8時間超・週40時間超）／月60時間超は50%／深夜22:00〜翌5:00は25%／法定休日は35%。 日8時間超で数えた分を週40時間超から差し引き、二重計上しません。
  • 労基則21条　家族手当・通勤手当など7種は割増基礎から除外。支払項目マスタの「割増基礎に算入」フラグで1件ずつ制御します。
  • 労基法34条　6時間超は45分、8時間超は60分の休憩義務。不足していれば勤務の詳細に警告を出します。
  • 労基法35条　国民の祝日は所定休日であって法定休日ではないため、祝日設定マスタの「法定休日」をONにした日だけを35%の対象にします。
  • 労基法39条　入社年月日から継続勤務年数を出し、有給付与マスタの日数を引きます。年5日の取得義務も一覧で追跡します。
  • 労基法109条　打刻を書き換えた場合、元の時刻・新しい時刻・実行時刻を履歴として残し、手入力の打刻には位置情報を付けません。

DESIGN DECISIONS

なぜこの作りにしたのか

業界で使われている既存の隊員向けアプリについて、アプリストアに公開されているレビューを調べたところ、 同じ種類の不満が繰り返し投稿されていました。それらは技術的にはいずれも解決可能なものです。 本プロトタイプでは、その一つひとつに具体的な設計で応えています。

現場で起きている問題本プロトタイプでの解決該当画面
日をまたぐ夜勤で出発報告ができない
0:00開始の勤務は、前夜に家を出る時点では「前日」扱いになり打刻できない		 勤務日と打刻日を別々に持ち、前夜からの出発報告を許可。該当シフトには「日跨ぎ夜勤・前夜出発可」と明示します。 スマホ ②
圏外・ピーク時に打刻できない
高架下やトンネル、朝夕の混雑時にサーバーへ到達できない		 打刻をまず端末内のキューに保存し、通信回復時に自動送信。件数を画面に表示して未送信を隠しません。 スマホ ③
給与明細が閲覧のみで印刷できない
紙の明細が廃止された一方、住宅ローン等で必要な控えが取れない		 明細画面からPDF保存・印刷を可能に。管制側からも同じ帳票を出力できます。 スマホ ⑧ / 帳票
暗所で画面が読めない
夜間現場でダークモード非対応だと白背景に白文字になる箇所がある		 全画面をライト／ダーク両対応で設計。時刻表示などの数値も両モードで検証済みです。 全画面
どの日を編集中か分からなくなる

勤務実績から給与を手計算している
深夜割増・残業割増・休憩控除を人が計算すると間違える		 ガントの打刻から実働・深夜・残業を自動算出し、深夜25%・残業25%を積み上げて支給額を出します。深夜かつ残業の時間は自動的に150%。打刻の矛盾や労基法34条の休憩不足も検知して警告します。 PC ④〜⑥

SCOPE

前提と制約

検討を進めるうえで誤解が生じないよう、このプロトタイプが「何ではないか」を明記します。

⚠ 確認しておきたいこと

  • これは UI 検証用のプロトタイプであり、実運用可能な製品ではありません。既存の警備システム製品のソースコードやデータを利用したものではなく、ゼロから実装したものです。
  • データはブラウザ内にのみ保存されます。サーバーもデータベースも存在しないため、別の端末とデータを共有することはできません。ログイン認証もありません。
  • 表示される情報はすべて架空のサンプルです。会社名・隊員名・現場名・金額・住所に実在のものは含まれません。
  • 担当者権限はメニューの出し分けであって、セキュリティではありません。担当者権限マスタで各メニューの表示を制御していますが、 ブラウザ内で完結する以上、開発者ツールから回避できます。実際のアクセス制御にはサーバー側の認証・認可が必須です。
  • 打刻の修正履歴は端末内にしか残りません。誰がいつ何を書き換えたかを記録していますが、 その記録自体を同じ端末から消せるため、労基法109条が求める保存の担保にはなりません。改ざん耐性のある保存先が必要です。
  • 実運用には別途バックエンドの構築が必要です。データベース、認証、権限管理、バックアップ、監査ログの保全、 複数端末でのデータ共有が該当します。これらはクライアントだけでは原理的に実現できません。
  • 賃金計算は代表的なケースを実装したもので、税務・労務の確認を経ていません。 日8時間超25%・週40時間超25%・月60時間超50%・深夜25%・法定休日35%・割増基礎への手当算入（労基則21条）・ 休憩の付与義務（34条）に対応していますが、変形労働時間制・裁量労働・年末調整・社会保険の資格得喪は未対応です。 実際の給与計算に用いる前に社会保険労務士の確認を受けてください。
